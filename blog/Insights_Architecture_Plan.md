# План архитектуры и навигации раздела Insights (Блог)

## Концепция
Раздел Insights должен ощущаться не как классический WordPress-блог, а как база знаний (Knowledge Hub) эксперта. Дизайн — минималистичный, фокус на тексте и безупречной типографике, переиспользование существующих компонентов (карточек, стеклянных панелей). Без оверинжиниринга: статический HTML/CSS, легко масштабируемый и невероятно быстрый (что очень любит Google).

## 1. Структура файлов и папок
Внутри текущей папки `site/` создается следующая структура:
```text
site/
├── index.html               # Главная страница
├── style.css                # Общие стили (переиспользуются)
├── script.js                # Общие скрипты
└── blog/                    # Новая папка для всех материалов (Insights)
    ├── insights.html        # Главный хаб-архив (список всех статей)
    ├── article-template.html# Эталонный шаблон, который ты будешь копировать для новых статей
    ├── article-1-name.html  # Реальная статья 1
    └── assets/              # Изображения, схемы, графики специфичные для статей
```

## 2. Логика навигации (User Flow)

### Шаг 1: С Главной страницы (`index.html`)
- В текущем блоке "Blog" выводятся только 2-3 последние (или закрепленные) статьи. Это "витрина".
- При клике на карточку статьи -> прямой переход на страницу статьи (например, `blog/article-1.html`).
- Под карточками располагается минималистичная кнопка `View all insights →` -> переход в хаб `blog/insights.html`.

### Шаг 2: Хаб-архив (`blog/insights.html`)
**Задача:** Удобный, стильный каталог всех твоих мыслей и кейсов.
- **Header:** Переиспользуем шапку с главной (Логотип слева). При клике на логотип пользователь **всегда** возвращается на `index.html`.
- **Заголовок страницы:** Крупно "Insights" + деликатный сабтайтл ("Заметки, кейсы и архитектура AI-систем").
- **Фильтрация (Опционально на вырост):** Стеклянные кнопки-теги (Pills) сверху: [All], [AI Strategy], [Process Design].
- **Сетка статей:** Красивый грид из карточек (можно сделать первую статью самой крупной, а остальные поменьше). Используются те же стили `case-card`, что и на главной.
- **Footer:** Тот же футер с призывом связаться и переходом обратно на главную.

### Шаг 3: Страница конкретной статьи (`blog/article-1.html`)
**Задача:** Идеальный опыт чтения. Глаза не должны уставать, фокус только на твоей экспертности.
- **Верхняя навигация (Sticky Header):** 
  - Слева: Кнопка `← Назад (All Insights)` (ведет на `insights.html`).
  - Справа: Твой Логотип (ведет на главную `index.html`).
- **Шапка статьи (Hero Article):**
  - Тег категории (например, `[ AI Strategy ]`).
  - Крупный заголовок (H1) — содержит главный запрос статьи (например, "Как ИИ сокращает время оценки объектов на 80%").
  - Мета-данные: Дата публикации и время чтения ("Oct 12 • 5 min read").
- **Тело статьи (Content Zone):**
  - **Ограниченная ширина:** Текст не на весь экран! Максимальная ширина текстового блока 650-700px. Это "золотой стандарт" комфортного чтения.
  - Стилизованные цитаты (blockquotes) для выделения главных инсайтов (например, стеклянная подложка с зеленой линией слева).
- **Подвал статьи (Next Steps):**
  - **Удержание:** Блок "Read Next" — 2 карточки других твоих статей.
  - **Конверсия (CTA):** Стеклянная плашка в самом низу с текстом: *"Нужна помощь с внедрением подобной архитектуры в ваш бизнес? → [Book a discovery call]"* (ведет на календарь).

## 3. SEO-логика (Почему это будет собирать трафик)
1. **Семантические URL:** Адреса вида `/blog/ai-in-real-estate.html` прекрасно читаются поисковиками.
2. **Изолированный контент:** У каждой статьи будет свой `<title>` и `<meta description>`. Это позволяет каждой статье ранжироваться в Google независимо по узким B2B-запросам (long-tail keywords). Главная страница ловит запрос "AI Architect", а статьи ловят запросы "process automation for real estate".
3. **Кросс-перелинковка (Internal Linking):** Гугл обожает, когда страницы связаны. Главная ссылается на Хаб -> Хаб на Статью -> Статья ссылается обратно на Главную и на другие Статьи. Вес сайта растет.
4. **Скорость:** Так как это статика (чистый HTML/CSS) без тяжелого бэкенда, скорость загрузки будет 100/100, что дает огромный буст в современном SEO (Core Web Vitals).

## 4. Итог: Что нужно сверстать
Чтобы запустить этот механизм, нам потребуется сделать всего 2 новых файла:
1. **`insights.html`** — каталог.
2. **`article-template.html`** — шаблон для чтения. 

В них мы просто подключим твой существующий `style.css` и добавим пару новых CSS-классов специально для красивого форматирования текста статей.
